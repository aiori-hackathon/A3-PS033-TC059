# DNS and Security side (Student A)

Signed `lab.test` zone, a validating resolver, and the records the client uses to discover the three diagnostic services. The client side is documented separately by Student B.

## What runs

| Component | Role | Address |
| --- | --- | --- |
| BIND 9.20 (`lab-bind`) | Authoritative server for `lab.test`. Signs the zone automatically (`dnssec-policy default`, inline signing, ECDSA P-256) | 127.0.0.1:5300 |
| Unbound (`lab-unbound`) | Validating resolver. Trusts only the zone's public key and sets the AD flag on answers that verify | 127.0.0.1:5301 |

The client queries Unbound (5301), never BIND directly.

## Records published

- `latency`, `traceroute`, `lossjitter` (A and SVCB): ports 8081, 8082, 8083 and `ipv4hint=127.0.0.1`
- `key65400`: private-use SVCB parameter holding the SHA-256 of each service's `/.well-known/descriptor.json`
- `_index._agents.lab.test`: TXT record with a JSON list of the three services
- All records are signed (RRSIG)

## Deliberately faulty entries (for negative tests)

| Name | Fault | Unbound returns |
| --- | --- | --- |
| `bogus.lab.test` | DS record matches no real key, so the chain of trust is broken | SERVFAIL |
| `malformed.lab.test` | Correctly signed, but the SVCB record has no port | NOERROR + AD (content unusable) |

`dig +cd` on `bogus.lab.test` returns 127.0.0.1, which shows validation alone causes the failure.

## Files

- `docker-compose.yml`: BIND and Unbound
- `config/named.conf`: BIND configuration and signing policy
- `zones/lab.test.zone`, `zones/bogus.lab.test.zone`: zone data
- `unbound/unbound.conf`: resolver configuration
- `unbound/lab.test.key`: public trust anchor (regenerated by the script below)
- `export-anchor.py` / `export-anchor.sh`: re-export BIND's public key as Unbound's trust anchor, then restart Unbound

## Run

    mkdir -p data && chmod 777 data
    docker compose up -d
    sleep 10
    python3 export-anchor.py      # Windows: python export-anchor.py

Run the anchor script every time on a new machine: BIND generates its own key on first start, so the committed anchor will not match.

## Check

    dig @127.0.0.1 -p 5301 latency.lab.test A +dnssec      # expect "ad" in flags
    dig @127.0.0.1 -p 5301 bogus.lab.test A                # expect SERVFAIL
    dig @127.0.0.1 -p 5301 malformed.lab.test TYPE64 +dnssec   # expect NOERROR + ad

## Security notes

- `data/` holds the private signing keys. It is git-ignored and must never be committed.
- Trust boundary: the client trusts only answers Unbound has validated (AD flag). DNSSEC proves the record is authentic; it does not prove the service is safe or that a caller is authorised.
- The trust anchor is shared manually because `lab.test` is not chained to the real DNS root.
- If you edit a zone file, increase its serial, or BIND will not re-sign.
